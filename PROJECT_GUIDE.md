   # BankAssistant — документация для передачи коллеге

   Краткий технический гайд по проекту: что внутри, как запустить, как обновлять базу знаний и шаблоны.

   Карта файлов API и ограничений: [API_LIMITS_MAP.md](./API_LIMITS_MAP.md).

   ## 1) Что это за сервис

   `BankAssistant` — backend + виджет для:
   - ответов по внутренней инструкции (с указанием пунктов-источников),
   - диалогового заполнения шаблонов,
   - генерации `.docx` документов.

   Проект ориентирован на локальный/контурный запуск (без внешних API по умолчанию).

   ## 2) Стек

   - **Python / FastAPI** — API
   - **Uvicorn** — ASGI-сервер
   - **docxtpl + python-docx** — генерация/обработка Word
   - **Локальный BM25-поиск** — поиск по базе знаний
   - **Собственный Python RAG** — локальный BM25-поиск и контролируемая сборка ответа
   - **Docker + Caddy** — контейнерный деплой и reverse proxy

   ## 3) Структура проекта

   - `app/main.py` — FastAPI-приложение и API-роуты
   - `app/dialog.py` — диалоговый движок (состояния сессии)
   - `app/knowledge.py` — поиск по базе знаний и формирование ответа
   - `app/render.py` — подстановка данных в `.docx` шаблоны
   - `app/ingest.py` — загрузка/обновление версии инструкции в `kb/chunks.json`
   - `app/compliance.py` — локальная проверка загруженных черновиков по пунктам Инструкции
   - `templates/templates.json` — метаданные шаблонов и поля
   - `kb/chunks.json` — база знаний (пункты инструкции)
   - `static/widget.js` — встраиваемый виджет
   - `tests/test_dialog.py` — тесты ключевого сценария

   ## 4) Быстрый запуск локально (Windows PowerShell)

   ```powershell
   cd Z:\BankAssistant
   py -3.14 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   python -m pip install -r requirements.txt
   python -m uvicorn app.main:app --reload
   ```

   Проверки:
   - `http://127.0.0.1:8000/api/health`
   - `http://127.0.0.1:8000/docs`
   - `http://127.0.0.1:8000/` (демо-страница)

   Остановка: `Ctrl + C`.

   ## 5) Запуск через Docker

   ```powershell
   cd Z:\BankAssistant
   copy .env.example .env
   docker compose up -d --build
   ```

   Сервисы:
   - `api` — FastAPI
   - `caddy` — reverse proxy

   ## 6) Переменные окружения (.env)

   См. `.env.example`.

   Ключевые:
   - `DOMAIN` — адрес/домен для Caddy
   - `ALLOWED_ORIGINS` — CORS
   - `AUTH_TOKENS` — роли доступа (`token:role,token:role`)
   - `ADMIN_TOKEN` — доступ к `POST /api/admin/kb/reload`
   - `AI_PROVIDER` — `local_rag` (основной режим) или `extractive`
   - `AI_CONFIG_PATH` — путь к JSON-конфигурации ограничений

   Для собственного локального RAG:

   ```text
   AI_PROVIDER=local_rag
   ```

   Вопрос не отправляется наружу: BM25 находит пункты локальной базы, а
   `LocalRAGAnswerer` собирает ответ только из найденных текстов.

   Файл `config/ai.json` уже добавлен как точка расширения для ограничений:
   `max_input_chars`, `max_output_tokens`, `min_relevance`, `allowed_topics`,
   `blocked_topics`, `requests_per_minute`. Значения `null`/пустые списки означают,
   что ограничение пока не включено.

   Если `AUTH_TOKENS` пустой, включается демо-режим (роль `employee` по умолчанию).

   ## 7) Архитектура и пользовательские сценарии

   Пользователь работает через [встраиваемый виджет](./static/widget.js) или Swagger.
   Виджет создаёт сессию, отправляет сообщения в FastAPI и показывает ответ, источники,
   релевантность, кнопки действий и ссылку на `.docx`.

   Основные сценарии:
   1. вопрос по инструкции → найденные пункты, краткое объяснение и источники;
   2. неоднозначный вопрос → один уточняющий вопрос;
   3. подготовка документа → выбор шаблона, сбор полей, подтверждение и генерация черновика;
   4. проверка готового черновика → загрузка файла, сопоставление с Инструкцией,
      процент соответствия и рекомендации;
   5. обновление Инструкции → `ingest`, затем `reload`, старая версия архивируется.

   Схема взаимодействия:
   `виджет → FastAPI → диалоговый движок → BM25 KnowledgeBase → активные пункты`
   `→ ответчик/LLM → ответ + sources`. Для проверки документов:
   `файл → compliance.py → KnowledgeBase → checks + recommendations`.
   Источник данных и ответчик разделены интерфейсами, поэтому можно подключить
   другие процессы, базы и векторный поиск без переписывания UI.

   ## 8) Основные API-эндпоинты

   - `GET /api/health` — здоровье сервиса
   - `GET /api/templates` — шаблоны для текущей роли
   - `POST /api/sessions` — старт сессии (`template_id` опционально)
   - `POST /api/sessions/{id}/messages` — сообщение в диалог
   - `GET /api/sessions/{id}/document` — скачать готовый `.docx`
   - `GET /api/kb/documents` — версии документов в базе знаний
   - `POST /api/admin/kb/reload` — перечитать `kb/chunks.json`
   - `POST /api/documents/review` — multipart-загрузка `.pdf/.docx/.txt/.md` и проверка черновика
   - `POST /api/sessions/{id}/feedback` — оценка последнего ответа и пользовательское исправление
   - `GET /api/admin/feedback` — просмотр накопленной обратной связи по `X-Admin-Token`

   ## 11) Обратная связь и обучение на ошибках

   Под ответом в виджете доступны кнопки «Да/Нет». Если ответ отмечен как ошибочный,
   пользователь может написать правильный вариант. Исправление сохраняется локально в
   `feedback/feedback.jsonl` и используется для похожих вопросов после перезапуска.
   Официальная база Инструкции при этом не изменяется автоматически: исправление
   передаётся модели только как подсказка для проверки, а источники Инструкции остаются
   приоритетными.

   ## 12) Как обновлять базу знаний (Инструкцию)

   1. Подготовить файл `.pdf`, `.docx`, `.txt` или `.md` с пунктами вида `3.4. Текст...`.
   2. Выполнить:

   ```powershell
   python -m app.ingest kb\Инструкция.docx --doc "Инструкция по документообороту" --version 2.0
   ```

   3. Применить без перезапуска API:

   ```powershell
   curl -X POST http://127.0.0.1:8000/api/admin/kb/reload -H "X-Admin-Token: <ADMIN_TOKEN>"
   ```

   Новая версия становится `active`, предыдущая автоматически архивируется.

   ## 13) Проверка готовых документов

   `POST /api/documents/review` принимает поле `file` и проверяет текст черновика
   по доступным активным пунктам для роли пользователя. Ответ содержит:
   - сопоставленные фрагменты и источники;
   - процент соответствия;
   - фрагменты без достаточного основания;
   - рекомендации, что проверить или дополнить.

   Файлы `.pdf`, `.docx`, `.txt` и `.md` размером до 5 МБ читаются во временный файл и
   удаляются после проверки. Это прототип проверки соответствия, а не юридическое
   заключение и не подтверждение согласования документа.

   ## 14) Как добавлять/менять шаблоны документов

   1. Положить `.docx` в `templates/`.
   2. Использовать маркеры `{{ field_name }}` в документе.
   3. Описать шаблон в `templates/templates.json`:
      - `id`, `title`, `keywords`, `file`, `output_name`, `roles`,
      - `source`, `visa`,
      - `fields` (типы: `text`, `date`, `int`, `phone`, `email`, `choice`).
   4. Перезапустить сервис.

   ## 15) Тестирование

   Быстрая проверка:

   ```powershell
   python tests\test_dialog.py
   ```

   Покрываются:
   - поиск и честный отказ при отсутствии данных,
   - уточняющие вопросы,
   - сценарий заполнения шаблона,
   - роли доступа,
   - валидация полей,
   - версионность `ingest`.

   ## 16) Ограничения текущего прототипа

   - Сессии хранятся в памяти процесса (для масштабирования нужен Redis/внешнее хранилище).
   - Поиск лексический (BM25 + стемминг), не векторный.
   - Демо-данные в `kb/chunks.json` и `templates/` — заменить на реальные документы.

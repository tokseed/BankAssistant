# Помощник по регламентам: виджет, API и автозаполнение документов

Часть решения по кейсу «Интеллектуальный помощник по работе с внутренними регламентами и документами»
(Банк России, Финтех Хаб). Здесь: pop-up виджет, REST API, диалоговое заполнение шаблонов .docx,
поиск по пунктам Инструкции с источниками, деплой.

> Важно: пункты Инструкции в `kb/chunks.json` и бланки в `templates/` — **вымышленные демо-данные**.
> Реальные синтетические документы из кейса загрузите по инструкциям ниже.

## Что покрывает требования кейса

| Требование кейса | Где реализовано |
|---|---|
| Pop-up виджет для корпоративного портала | `static/widget.js`, одна строка подключения, Shadow DOM |
| Ответы со ссылками на пункты, % релевантности | `app/knowledge.py` (BM25), блок «Источники» в виджете |
| Не фантазировать, честно сказать «нет информации» | порог `MIN_RELEVANCE`, режим дословной выдержки, `test_no_answer_is_honest` |
| Объяснять простым языком | поле `plain` у пункта (демо) или локальная LLM с запретом выходить за найденные пункты |
| Уточняющие вопросы | короткий вопрос → кнопки этапов; при заполнении шаблона поле за полем с проверкой |
| Поиск шаблона и автозаполнение | `app/dialog.py` (намерение «нужна записка» → шаблон), `app/render.py` (docxtpl) |
| Вопрос по инструкции посреди заполнения | вопрос со знаком «?» → ответ с источниками → возврат к текущему полю |
| Матрица визирования | после генерации: кто согласует и сроки (`visa` в `templates.json`) |
| Версионность и актуализация | `python -m app.ingest` + `POST /api/admin/kb/reload`; старые версии получают статус archived |
| Роли и доступ | `AUTH_TOKENS`, `roles` у шаблонов, `access` у пунктов: чужие пункты не участвуют в поиске |
| Защита данных при работе с LLM | локальная Ollama, маскирование e-mail и номеров перед запросом, тексты вопросов не логируются |
| Работает локально, open source | FastAPI, docxtpl, Ollama; без внешних API |
| Проверка готовых документов | `POST /api/documents/review`, `app/compliance.py`, рекомендации и % соответствия |
| Расширение на другие процессы и источники | раздел «Архитектура и расширение», отдельные слои KB/ответчика/UI |

## Подключение к порталу

```html
<script src="https://ВАШ-ДОМЕН/static/widget.js" async data-token="ТОКЕН_ОТ_ПОРТАЛА"></script>
```

Атрибуты: `data-title`, `data-color`, `data-position="left"`, `data-template="memo"`, `data-api`, `data-token`.
Токен портал подставляет сам (из SSO-сессии), роль определяется на сервере.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/sessions` | начать диалог `{template_id?}` |
| POST | `/api/sessions/{id}/messages` | сообщение `{text}` → `{messages, options, sources, progress, download_url}` |
| POST | `/api/chat` | временный обычный чат с нейросетью `{message}` |
| GET | `/api/sessions/{id}/document` | скачать .docx |
| GET | `/api/templates` | шаблоны, доступные роли |
| GET | `/api/kb/documents` | документы и версии в базе знаний |
| POST | `/api/documents/review` | загрузить `.docx/.txt/.md` черновик и получить проверку по Инструкции |
| POST | `/api/admin/kb/reload` | перечитать базу (заголовок `X-Admin-Token`) |
| GET | `/api/health`, `/docs` | проверка, Swagger |

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload          # http://localhost:8000
python tests/test_dialog.py            # 10 тестов диалога и базы знаний
```

### GigaChat API

Скопируйте `.env.example` в `.env` и заполните ключ авторизации:

```env
AI_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=ключ_авторизации_из_кабинета
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

Приложение само получает OAuth access token, кэширует его до истечения срока и
обновляет при необходимости. Токен доступа не хранится в файлах.

В основном виджете используется совмещённый режим: сначала выполняется поиск по
локальной базе знаний, а если подходящих пунктов нет, вопрос передаётся в GigaChat
как обычный чат. Ограничения из `config/ai.json` применяются к общим сообщениям;
пустые значения и пустые списки означают, что соответствующее ограничение выключено.

### Проверка готового документа

Черновик можно отправить в `POST /api/documents/review` как multipart-поле `file`.
Поддерживаются `.docx`, `.txt` и `.md`, размер ограничен 5 МБ. Сервис не сохраняет
загруженный файл после проверки: каждый фрагмент сопоставляется с доступными пунктами
активной версии базы знаний и возвращаются процент соответствия, источники и
рекомендации по фрагментам без достаточного основания.

Пример:

```bash
curl -X POST http://127.0.0.1:8000/api/documents/review \
  -F "file=@черновик.docx"
```

## Загрузка настоящей Инструкции (новая версия)

```bash
# файл .docx/.txt/.md с нумерацией «3.4. Текст…» положите в kb/
python -m app.ingest kb/Инструкция.docx --doc "Инструкция по документообороту" --version 1.0
curl -X POST https://ДОМЕН/api/admin/kb/reload -H "X-Admin-Token: $ADMIN_TOKEN"
```
Новая версия того же документа становится активной, прежняя уходит в архив. В контейнере:
`docker compose exec -u root api python -m app.ingest kb/Инструкция.docx --doc "..." --version 2.0`.
Ограничение доступа к пункту: в `kb/chunks.json` поле `"access": ["manager"]`; пункты «простыми словами»: поле `plain`.

## Подключение настоящих бланков (модульных документов)

1. В Word впишите `{{ ключ }}` там, где подставляются данные (латиницей, без смены форматирования внутри метки), положите файл в `templates/`.
2. Опишите шаблон в `templates/templates.json`: `id`, `title`, `keywords` (по ним находят бланк по словам пользователя), `file`, `roles`,
   `source` (пункт Инструкции), `visa` (согласующие и срок из матрицы визирования), `fields` (типы: text, date, int, phone, email, choice; `"required": false`).
3. Перезапуск: `docker compose up -d --build`.

## Деплой на VPS

```bash
curl -fsSL https://get.docker.com | sh
cp .env.example .env && nano .env      # DOMAIN, AUTH_TOKENS, ADMIN_TOKEN
docker compose up -d --build           # HTTPS выпускает Caddy
# локальная LLM (по желанию, нужно ~8 ГБ ОЗУ для модели 7B):
docker compose --profile llm up -d
docker compose exec ollama ollama pull qwen2.5:7b-instruct
# затем в .env: LLM_URL=http://ollama:11434  LLM_MODEL=qwen2.5:7b-instruct  и  docker compose up -d
```
Публичная ссылка для жюри: `https://ВАШ-ДОМЕН/`.

## Сценарий демонстрации (по пунктам защиты)

1. «Сколько дней даётся на согласование?» → ответ, пункт 3.4, релевантность.
2. «Согласование» (одно слово) → уточняющие кнопки этапов.
3. «Какой курс доллара?» → честное «информации нет» + куда обратиться.
4. «Как оформить служебную записку?» → ответ + кнопка «Заполнить: Служебная записка».
5. Заполнение с проверкой дат; посреди заполнения вопрос «Какие реквизиты обязательны?» → ответ и возврат к полю.
6. Скачать .docx, показать согласующих по матрице визирования.
7. Роли: поручение видят только `manager`/`expert`.
8. Новая версия Инструкции: `ingest` → `reload`, ответ меняется, старая версия в архиве.
9. Отправить `черновик.docx` в `POST /api/documents/review` и показать процент соответствия,
   источники и рекомендации по фрагментам без основания.

## Архитектура и расширение

Поток запроса: `static/widget.js` → FastAPI (`app/main.py`) → `app/dialog.py` →
`KnowledgeBase` (`app/knowledge.py`) → BM25-поиск по активным пунктам
`kb/chunks.json`. Найденные пункты передаются в extractive-ответчик или подключённую
LLM; ответ возвращается вместе с источниками и релевантностью. Для документов поток
идёт через `POST /api/documents/review` → `app/compliance.py` → тот же поиск.

Слои разделены так, чтобы добавлять другие процессы: новый источник подключается
через замену/расширение `KnowledgeBase`, новый тип документа — через шаблон и
`templates/templates.json`, новый процесс — отдельным обработчиком без изменения
виджета. Роль приходит из `AUTH_TOKENS`, а поля `roles` и `access` ограничивают
шаблоны и пункты до поиска.

## Ограничения прототипа

* Поиск лексический (BM25 + грубый стемминг и синонимы). Для продакшена замените `KnowledgeBase.search()` на эмбеддинги
  (например, bge-m3 + Qdrant): интерфейс диалога не изменится.
* Режим LLM (Ollama) написан, но в этой среде не запускался: проверьте на своём сервере.
* Сессии в памяти одного воркера, файлы в `/tmp` 30 минут; для кластера нужен Redis.
* Склонение ФИО по падежам не делается: бланки в именительном падеже.
